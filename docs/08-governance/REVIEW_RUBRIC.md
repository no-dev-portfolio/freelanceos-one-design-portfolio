# 設計レビュー・ルーブリック

各観点 0〜5点（0=未検討、1=懸念多数、3=成立仮説あり、5=実測で確認済）。机上設計しかない場合、原則4以上を付けず「目標点」と区別する。

| 観点 | 否定的に確認する質問 | 必須証拠 |
|---|---|---|
| 顧客価値 | 実際の仕事の何分を削減するか? | シナリオと利用者検証 |
| 機能 | 最初のリリースに不要な機能は? | 優先度/非対象 |
| UI/UX | 説明なしに使えるか? エラー時は? | 画面試作と試用記録 |
| デザイン | 視認性・認知負荷・アクセシビリティは? | トークン・コントラスト結果 |
| ナレッジ | AIが覚えた事実は本当に正しいか? | 版・出典・検証証拠 |
| 成長 | 記憶が成績を悪化させないか? | A/B比較・未見テスト |
| セキュリティ | 悪意のあるMarkdownで越権するか? | Threat model・攻撃試験 |
| 整合性 | 同時編集やクラッシュで失わないか? | CAS・復旧PoC |
| 運用 | 復元、データ削除、コスト上限は? | RPO/RTO・上限試験 |
| 実装可能性 | もっと簡単な方法は? | ADR・代替案比較 |

**CR-002の合格規則:** 仕様審査G5-Dと実装後の有効化/運用受入G5-Rを分離する。机上で処置できるCriticalの記述欠陥は修正し、実装依存の実証は担当/期待値/停止/差戻し先付きで登録する。実機未実施だけで仕様審査を循環させない。運用はCritical失敗/未検証capabilityを無効・隔離し、Highは人間の明示受容と隔離。点数平均や文書検査で実証合格を代用しない。重要方針の人間採否/独立審査は別記。
