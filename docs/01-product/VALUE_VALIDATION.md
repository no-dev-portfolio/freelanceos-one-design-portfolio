## 質問と証拠
1. 直近の同種問題の頻度、探す資料、やり直し、時間の内訳を聞く。架空例に置換し秘密を収集しない。
2. 「今日→依頼→根拠→訂正→検証→承認→復旧」の文書storyboardを見せ、次に押すもの/何が起きるかを本人の言葉で説明してもらう。
3. 「同じ入力で再開」と「訂正して新規」、「Passed」と「Verified」、「停止要求」と「停止完了」の理解を確認する。
4. 機密由来jobのCloud不可、差分を見られないmobile承認不可、未知writerの適用不可が仕事を止める頻度を聞く。安全規則を黙って弱めない。
5. 検証/承認/復旧に許容できる確認負担と、既存手段が優れる場面を聞く。

対象役割、説明資料版、質問、匿名化した所見、迷った箇所、改善案を保存。5名は形成的問題発見の初期案で、90%成功や時間削減を立証したとしない。参加者未確保のため今回実施済みとしない。実操作/読み上げ/処理時間/成長効果の測定は実装後のUX/EVAL試験へ戻す。
