# DOC-03 詳細画面仕様書

共通：最小幅320px、PC標準1440px想定。フォーカス可視化、説明可能な状態名、タッチターゲット44px以上を設計目標とする。画面内文言は日本語。配色は選択とステータスを色だけで表現しない。

## SCR-00 初回設定ウィザード
**目的:** 最初に安全な動作範囲を決める。**要素:** 利用目的→Vaultパス→機密送信方針→利用モデル→デモ確認。**操作:** Vault指定、権限テスト、サンプルで練習、後で接続。**検証:** 外部送信のデフォルトOFF、Vault外を読まない、失敗時は完了扱いにしない。**状態:** 接続成功/未指定/読取不能/権限拒否/中断。関連 REQ-KB-001, REQ-AI-002。

## SCR-01 今日（ホーム）
**目的:** 重要作業と要承認事項を把握。**主要素:** 今日の優先事項3件、完了報告、承認n件、簡易依頼、同期状態。**操作:** 作業詳細、承認、依頼開始。**状態:** 初回空状態、処理中、警告、全完了、オフライン。**禁止:** KPIの羅列、架空のタスクを本物らしく表示。関連 REQ-UX-001。

## SCR-02 仕事一覧
**目的:** 継続中の仕事に戻る。**要素:** 状態（Draft/Planned/Running/WaitingApproval/Blocked/CancelRequested/OutcomeUnknown/Completed/Failed/Cancelled）、目的・最終更新・成果物。**操作:** 絞込、再開、アーカイブ。**異常:** 失敗タスクを消さず手動復旧への導線。関連 REQ-UX-002。

## SCR-03 仕事詳細
**目的:** 何をしているか・どこまで安全に任せられるか理解。**要素:** 依頼・制約、Planステップ、根拠、実行イベント、成果物、停止/再開、知識候補。**操作:** 計画変更要求、停止、承認、成果物確認。**制約:** 取消しても外部送信済み操作を取り消したように表示しない。関連 REQ-AI-003。

## SCR-04 知識検索
**目的:** 技術用語・障害から検証可能な知識を探す。**要素:** 検索欄、フィルター（領域/検証状態/対象版/機密）、ヒット箇所、最終検証日。**操作:** 検索、詳細へ、Obsidianで開く（URIは明示承認のローカル操作）。**異常:** 索引遅延時の警告、出典不足時の不明表記。関連 REQ-KB-003。

## SCR-05 知識詳細
**目的:** 本文・根拠・適用範囲を確認。**タブ:** 読む/根拠/関係/履歴。**要素:** note_id、revision、validation_status、scope、sources、利用履歴、現在のVault同期状態。**操作:** 編集をObsidianで開く、訂正候補、失効申請。**異常:** 参照版が失効・変化した場合に評価済みと表示しない。関連 REQ-KB-002/008。

## SCR-06 承認一覧
**目的:** 要判断項目を過不足なく捌く。**要素:** リスク、種類（知識更新/外部送信/重要変更）、期限、影響、提案理由。**操作:** 一件開く、低リスク類似案件をまとめて閲覧（実行承認は一件ずつ）、差戻し。**異常:** 期限切れを自動実行しない。関連 REQ-UX-003。

## SCR-07 変更差分・承認
**目的:** 人が影響範囲を理解して意思決定。**要素:** Base rev/hash、変更後、行差分、根拠、テストID、対象環境、機密区分、不可逆性。**操作:** 承認、差戻し、再検証、キャンセル。**不変条件:** 実行対象のハッシュが承認値と異なれば承認失効。**異常:** 同時編集衝突をMerge案として表示、AIの自動上書き禁止。関連 REQ-KB-005, REQ-AI-004。

## SCR-08 根拠・実行履歴
**目的:** トラブル調査と品質検証。**要素:** step_id、tool_id、入力ハッシュ、出力概要、モデル、トークン/費用、結果、引用ノート版、PIIマスク。**操作:** ログエクスポート（マスク有）、課題起票。**異常:** ログに秘密情報を露出しない。関連 REQ-OPS-002。

## SCR-09 設定・接続
**目的:** Vault・モデル・権限・予算・バックアップ。**要素:** Vault状態、送信ポリシー、データ分類、接続先、費用上限、復元テスト日。**操作:** 設定変更、接続テスト、バックアップテスト。**異常:** 失敗設定を黙って保存しない。関連 REQ-OPS-001/003。

## SCR-10 成長評価（二次画面）
**目的:** 成長を過大表示せず測る。**要素:** 記憶あり/なしの差、未見タスク、誤引用、再発率、確認工数、評価セット版、信頼区間。**操作:** 評価詳細、再測定計画。**禁止:** ノート件数を知能スコアと称しない。関連 REQ-EVAL-001/003。

## 設計レビュー観点
各画面について初回利用者の思考発話、空状態、ロード、長い日本語、フォント拡大、キーボード、通信断、権限拒否、二重クリック、再読込、ブラウザ戻るを確認する。

## v0.10 状態別の操作・復帰先（CR-001設計候補）

全mutationはoperation_idを表示状態へ結び付ける。二重押下は同じIdempotency-Keyで同じ結果を取得し、戻る/再読込で新keyを発行して再実行しない。通信断は「結果を確認中」、operation照会不能は「結果不明・再送しない」。state_version/sequenceが古いeventは適用せずsnapshot再取得。停止は「停止要求済み」と「停止完了」を分ける。

| 画面 | 通常の完遂導線 | 異常と文言・可能操作 | 次画面/保存する状態 |
|---|---|---|---|
| SCR-00 初回 | Vault/分類→能力test→架空demo→01 | 拒否は「読取権限を確認」。modelなしは「AI実行不可」、09へ。接続を後回しは閲覧modeだけ | 入力保存、再開。未確認能力を完了表示しない |
| SCR-01 今日 | 依頼→添付分類→model/費用→plan→03 | 送信前の対象/同意preview。空状態は架空demoと実作業を区別 | Draft IDを保存、入力を失わない |
| SCR-02 一覧 | state別に03を開く | OutcomeUnknownは照合へ、Cancelledの再開は新attempt。archiveは非表示だけで取消ではない | filterと選択job保持 |
| SCR-03 仕事 | Plan確認→実行→成果物→候補 | CancelRequestedは待機、OutcomeUnknownは08で既知効果照合。model/権限/予算不足は09へ | job/attempt/sequence、成功step保持 |
| SCR-04 検索 | scope/filter→hit→05 | 「該当なし」と「索引を確認できない」を区別。権限外の存在は示さない | query/filter、staleは本文表示停止 |
| SCR-05 知識 | 使用版/現在版/検証hash→訂正候補→07 | 失効は本文を隠し理由と再検証導線。候補と通常知識の検索を混ぜない | note_id/hash、引用箇所保持 |
| SCR-06 承認 | risk/期限で一件→07 | 一括は閲覧のみ。期限切れは再提案、権限不足は操作不可 | action_id/一覧filter、件数再取得 |
| SCR-07 差分 | 元/現在/提案と作用先→承認→operation照会 | hash/policy変化は「内容が変わったため再確認」。mergeは新候補/新承認。claim後取消は不可逆点表示 | 旧承認を使わず、差戻し理由付き再提出 |
| SCR-08 履歴 | step/action/operation/evidence照合→03 | 不明結果は人間の照合証拠入力。exportはマスクpreview/対象期間/保存結果 | correlation、原文secretを表示しない |
| SCR-09 設定 | 能力/権限/同意/上限/backup→元作業 | policy縮小で進行job再認可。復元は隔離preview、鍵不明/失効台帳なしは公開不可 | return_toとDraft保持、未検証設定を成功保存しない |

### モバイル・アクセシビリティ・進捗

320px/200%文字拡大で差分・作用先・根拠を欠かさず確認できなければ承認buttonを無効にし、PCへ同じaction hashを引き継ぐ。remote/mobile接続自体は認証/TLS設計受容まで未提供。全画面でtab順・見出し・label・エラー関連付け、状態更新のlive通知（秘密を読上げない）、dialog閉鎖後のfocus復帰を定義する。処理中は測定不能な%を表示せず「索引確認中」等のstepと最終確認時刻を出す。Reduced Motionと長文日本語を確認する。WCAG 2.2 AAは目標で実測未済。

[文書ストーリーボード](../../wireframes/STORYBOARD.md) は机上の状態遷移資料。操作できるUI試作や利用者試験の代わりではない。TEST-UX-001〜006を満たす操作試作/試用は未実施。

## v0.11 CR-002の完遂・異常導線

- SCR-00/03/09：能力と送信先だけでなくjob taintを表示。「機密由来の入力があるためCloud不可」を理由として示し、要約したからpublicへ変更する操作を提供しない。
- SCR-03/07：送信previewはadapter構築後の最終envelope。宛先/model/会話/添付変更は旧同意失効と再確認を表示。送信claim後の取消は回収不能/結果照合を明記。
- SCR-02/03：「同じ入力で再開」と「訂正して新しい仕事へ」を分離。訂正はfork、旧計算結果は自動転用しない。元副作用の完了/不明と再送禁止を常に引き継いで表示する。
- SCR-03/05：「検証を依頼」→SCR-08で対象hash/claim/suite/scope/結果→SCR-07「証拠を採用」→SCR-05で検証証拠。権限不足/未知suite/旧hashは採用不可、失敗/timeoutはReviewedのまま訂正へ戻す。PassedとVerifiedを別labelで表示。
- SCR-03/04/05/07/08：本文・差分・snippet・LLM出力は [CONTENT_PRESENTATION](CONTENT_PRESENTATION.md) の非実行text。外部画像/自動linkなし。exportはtext/JSON preview、期間/保存結果/分類由来を保持する。

これらの導線は机上設計。実操作、focus/読み上げ、CSP、通信遮断は実装後に確認し、失敗時は設計と試験を更新する。

## v0.12 認証・一覧の画面契約

screen-api-contracts.jsonは全11画面の必須method/pathの検査用正本。SCR-00はnative pairing承認→code入力→session/CSRF取得、失敗は再発行案内で完了表示しない。SCR-02の一覧はGET /jobs、候補審査はGET /knowledge/candidatesと専用detail、SCR-09はGET /settingsとGET /consentsから現在版を読んで変更する。SCR-09でsession更新/個別失効/logoutを提供し、失効時は未実行操作を止めSCR-00へ戻す。戻り先はローカル画面IDのallowlistだけ。

初回sliceで提供しないwrite/Cloud/復元/評価操作は機能未提供と理由を表示して無効化。APIでも同じscopeで拒否し、read-only候補生成を製品の価値実証完了と表示しない。
